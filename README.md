# NeuroMita.CustomModels

A BepInEx plugin that loads **custom character models** into [NeuroMita](https://github.com/VinerX/NeuroMita) — a fan-made Unity project where you talk to Mita characters driven by language models.

It replaces a character's skinned meshes with meshes from an external model pack, while keeping the game's skeleton, animations, IK and interaction systems intact.

> **Status: the FBX path is complete and verified.** Two independent packs from different authors
> install end-to-end with **zero hardcoded correction values** and zero failed operations:
>
> | Pack | Skeleton root | Bones (body) | Alignment residual |
> |---|---|---|---|
> | CJ Mita | `Mita Skeleton` | 33 | — |
> | Gothic Mita (body/hair/sweater) | `Mita Skeleton no hair` / `Mita Skeleton Hair` | 64 / 13 / 11 | **0.0000** |
>
> Gothic Mita installs as `created=1 replaced=3 textured=3 removed=7 failed=0`.
>
> The **AssetBundle path is not viable at runtime** on this game and is not implemented — see
> [AssetBundle packages](#assetbundle-packages-why-they-are-not-supported-at-runtime).

## Why this works at all

NeuroMita's characters use the same skeleton layout as MiSide's (`Mita Skeleton`, bones named `Hips` / `Spine` / `Chest` / `Neck2` / `Neck1` / `Head` / `Left arm` / `IndexFinger3_R` …), and both are Unity **Humanoid** rigs. Model packs authored against that skeleton therefore bind correctly without any re-rigging in Blender.

What still varies between packs is the **overall orientation** of the exported mesh — different authors, different Blender versions, different FBX export settings. This plugin does **not** hardcode a correction angle for that. Instead it solves the alignment at runtime from the two skeletons' bind poses (see [Auto-align](#auto-align)).

## Features

- **Two package formats**
  - **Unity AssetBundle** (`UnityFS` header; `.vrmmod` and similar) — meshes, skeleton, bind poses, materials and textures come straight from Unity, no third-party parser involved.
  - **FBX pack directory** (`*.fbx` + texture + `addons_config.txt`) — the native format of *Miside Custom Models Loader*.
- **Automatic alignment** — no hardcoded rotation; solved from bind poses, with a residual error reported per bone set.
- **Bind poses taken from the game's own mesh** — the skeleton belongs to the game, so the binding transform must come from the game.
- **Weight normalisation** — per-vertex influences are taken as top-4 by weight and renormalised.
- **Target selection by Avatar name** — reliable, unlike GameObject names (a scene can contain dozens of unrelated Animators).

## Requirements

| | |
|---|---|
| Game | NeuroMita (Unity 6000.3.12f1, IL2CPP, metadata v39) |
| Loader | **BepInEx 6.0.0-be.788** or newer for IL2CPP win-x64 |
| Runtime | .NET 6 SDK (to build) |

Older BepInEx 6 builds cannot parse this game: its bundled LibCpp2IL only supports metadata up to v31, while the game ships v39. (`6.0.0-pre.2` reports `23-29`, `be.788` reports `23-106`.)

## Building

The build needs the path to your game installation (the folder containing `NeuroMita.exe` and `BepInEx\`). Give it in any of three ways:

```bash
# 1. command line
dotnet build -c Release -p:GameDir="D:\Games\NeuroMita"

# 2. environment variable
set NEUROMITA_DIR=D:\Games\NeuroMita
dotnet build -c Release

# 3. a game.dir file at the repo root containing the path on one line
echo D:\Games\NeuroMita > game.dir
dotnet build -c Release
```

`BepInEx\interop\` must already exist — it is generated by BepInEx on the game's first launch. If the build complains it is missing, start the game once with BepInEx installed.

## Packaging a release

```powershell
powershell -File package.ps1
```

Produces `dist\NeuroMita.CustomModels-<version>.zip` containing the plugin, `AssimpNet.dll`, the
native `assimp.dll` and the docs — everything a user needs. Pass `-GameDir "D:\Games\NeuroMita"` to
also deploy straight into a game folder.

## Installing

**Step-by-step guide: [docs/INSTALL.md](docs/INSTALL.md)** ·
**When something breaks: [docs/FAQ.md](docs/FAQ.md)**

The short version:

1. Install **BepInEx 6.0.0-be.788 or newer** (IL2CPP, win-x64) into the game folder, then launch the
   game once so BepInEx generates `BepInEx\interop\`.
   Older BepInEx builds cannot read this game's metadata (v39) and fail at startup with
   `Unsupported metadata version found! We support 23-31, got 39`.
2. Copy **three** files into `<Game>\BepInEx\plugins\`:
   `NeuroMita.CustomModels.dll`, `AssimpNet.dll`, `assimp.dll`.
   All three are in the release zip — nothing needs to be downloaded or compiled separately.
3. Put model packs into `<Game>\CustomModels\`, one subfolder per pack.
4. Launch the game, enter a scene containing a Mita, and check `BepInEx\LogOutput.log`
   for `INSTALL RESULT ... failed=0`.

## Configuration

Currently configured by constants in `Plugin.cs` (`ModelRuntime`):

| Constant | Meaning |
|---|---|
| `PackagePath` | Path to the model pack (a `UnityFS` file, or an FBX pack directory) |
| `TargetAvatarKeyword` | Which character to replace — matched against the Animator's **Avatar name**, e.g. `Crazy` for `CrazyMitaAvatar` |
| `TargetRendererKeyword` | Which renderer on that character to replace, e.g. `Body` |

A proper config file and in-game picker are on the roadmap.

## How it works

```
ModelPackage.Open(path)
   ├─ UnityFS header      → AssetBundlePackage  (AssetBundle.LoadFromFile)
   └─ directory / .fbx    → FbxDirPackage       (AssimpNet)

ModelApplier.Apply(renderer, part, skeletonRoot)
   ├─ 1. AutoAlign.Solve(targetBindPoses, modelBindPoses) → Matrix4x4
   ├─ 2. clone mesh, transform vertices & normals by that matrix
   ├─ 3. bind poses: looked up by bone name from the game's own mesh
   ├─ 4. bone array: mapped by name, index-preserving (missing → skeleton root)
   └─ 5. assign sharedMesh / bones / rootBone
```

### Auto-align

Three same-named bones (e.g. `Hips`, `Spine`, `Left leg`) are sampled from both skeletons in bind-pose space. Two orthonormal bases are built from them and the rigid transform between the bases is solved:

```
rot = basisTarget * transpose(basisModel)
fix = Translate(targetOrigin) * rot * Translate(-modelOrigin)
```

A different triad is tried if the first choice is missing or degenerate. Afterwards, **every** shared bone is used to compute the average residual position error, which is logged — a large residual means the two skeletons are not actually the same rig and the pack should not be trusted.

Because the transform is derived rather than assumed, packs exported with any orientation go through the same code path.

### Bind poses

`bindpose` is the inverse of a bone's transform at binding time. The bones belong to the **game**, so the binding transform must come from the game's original mesh, looked up by bone name — not from the model pack. Using the pack's own bind poses produces a rotation mismatch on every bone even when the skeletons are nominally identical.

### Bone mapping

Bones are matched **by name**, and the index mapping is kept 1:1 with the pack's bone list so that the mesh's `boneWeights` indices stay valid without re-sorting. Bones that cannot be found fall back to the skeleton root and are counted in the log.

## AssetBundle packages (why they are not supported at runtime)

`.vrmmod` and other `UnityFS` packs are **not loadable at runtime** on this game. This was
investigated thoroughly; every route is blocked by the same underlying cause — **the game never
uses AssetBundle itself** (all assets ship inside the build), so the subsystem is never
initialised and the type is never registered:

| Route | Result |
|---|---|
| `AssetBundle.LoadFromFile(string)` | `MissingMethodException: Il2CppSystem.ReadOnlySpan<T>.GetPinnableReference()` |
| `AssetBundle.LoadFromMemory(Il2CppStructArray<byte>)` | array allocation is broken — `Length` reads back garbage |
| `AssetBundle.LoadFromStream(Stream)` | needs `Il2CppSystem.IO.Stream`, which cannot be obtained |
| native `il2cpp_runtime_invoke` | `Il2CppClassPointerStore<AssetBundle>.NativeClassPtr == 0` |

The first two are Il2CppInterop generation defects (this game is Unity 6000.3 / metadata v39);
the last one is fatal and independent of them.

**Workaround**: convert the pack offline with UnityPy into a format this plugin can read, or use an
FBX version of the pack if one exists. Most MiSide model packs are published in the FBX format,
which is fully supported.

## Known limitations

- Only one renderer per character is replaced so far; packs that split body/hair/clothes across several meshes will only get their first mesh swapped.
- Facial expressions are lost when the game's `FaceLayer` is hidden. That mesh carries the school-uniform collar in addition to the face, so it collides with a replacement model. Nothing maps pack BlendShapes onto the game's expression system yet.
- Hair and skirt cloth physics (MagicaCloth2) are not re-bound — expect stiff or misbehaving hair on replacement models.
- Hand IK targets and item mount points still reference the original bones.
- Packs whose skeleton is named differently (Mixamo `mixamorig:*`, VRM) are not supported yet, even though both sides are Humanoid. The bones must currently share names with the game skeleton.
